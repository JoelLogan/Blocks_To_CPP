## Adding an IPC command

1. Add the request and response types and the `COMMANDS` entry in `crates/b2c-ipc`, then
   regenerate (`B2C_UPDATE_IPC=1 cargo test -p b2c-ipc --features ts --test generate`): the
   TypeScript client, the isolation allowlist and the isolation samples follow.
2. Implement the method on `b2c_app::Backend`.
3. Add a thin adapter in `src-tauri/src/commands/<area>.rs` and its path to `generate_handler!`
   in `src-tauri/src/lib.rs`.
4. Add `allow-<name>` (underscores become dashes) to `capabilities/main-window.json`; `build.rs`
   takes the command names from `b2c_ipc::COMMAND_NAMES` and writes
   `permissions/autogenerated/<name>.toml` (commit it).
5. `cargo test -p blocks2cpp-desktop --test consistency` checks that all five places agree.

The command also gets a row in [02 §2.5.2](../spec/02-architecture.md#252-commands), in the same
pull request ([security settings](desktop-security.md#security-settings) say why each command
needs its own permission).

## Adding a dependency

1. Check it against the policy: an exact version at least 7 days old, no weaker publishing
   provenance than its earlier versions, no install scripts, and for npm no git or tarball
   sub-dependencies ([packages/README.md](../../packages/README.md),
   [08 §8.9](../spec/08-security.md#89-supply-chain)).
2. Add a row to the table in [dependencies](dependencies.md): version and release date, licence,
   and why, with what it brings in.
3. Say why in the pull request (purpose, maintenance, licence, size, transitive count), as
   [CONTRIBUTING.md](../../CONTRIBUTING.md#rules-for-every-change) asks.

## Subclassing a Blockly class

[ADR-0014](../adr/0014-extending-blockly.md) allows public and protected members of documented
Blockly and plugin classes, registry replacements and drag strategies, never private members.
Add the subclass to the [list of Blockly seams](desktop-architecture.md#blockly-seams-adr-0014),
with what it overrides or uses and the version it was checked against, in the same pull request.
A workaround of an upstream defect also gets a report drafted in
[`docs/plans/upstream/`](../plans/upstream/README.md).

## Running the frontend in a browser

`pnpm --filter @blocks2cpp/desktop dev` starts only the Vite dev server
(<http://localhost:1420>), so the frontend can be opened in a browser. There is no backend there:
the window starts without one (development builds only), and calls to it fail. To run the whole
app from the dev server, see [Develop](../../BUILDING.md#develop) in `BUILDING.md`.

## Checking the app as it ships

In `tauri dev` the window loads the page from the Vite dev server, which sends no Content Security
Policy. To check the app as it ships, with the CSP and the embedded frontend, build it as
[`BUILDING.md`](../../BUILDING.md#develop) describes; `--debug` keeps the build quick.

## Regenerating the icons

`src-tauri/icons/icon.svg` is the source. To regenerate the other icons, from the repository
root:

```sh
pnpm --filter @blocks2cpp/desktop tauri icon src-tauri/icons/icon.svg -o /tmp/b2c-icons
cp /tmp/b2c-icons/{32x32.png,128x128.png,128x128@2x.png,icon.png,icon.ico} apps/desktop/src-tauri/icons/
```

Only these five are used (`bundle.icon` in `tauri.conf.json`): the macOS, Windows Store and
mobile icons that `tauri icon` also writes are not needed.

## Moving documentation

When a document is split or cut down, check that its text was moved, not lost, with
[`tools/check-moved-text.py`](../../tools/check-moved-text.py). It compares the old file (as it
was at a commit) with the files its text went to, sentence by sentence, and fails on a sentence
that is in none of them and not listed as dropped on purpose. For example, for the split of the
desktop app's README:

```sh
python3 tools/check-moved-text.py apps/desktop/README.md --rev d4dfafb \
  apps/desktop/README.md apps/desktop/e2e/README.md docs/developer-guide/*.md \
  BUILDING.md CONTRIBUTING.md --dropped docs/plans/m2-polish-w6-2-dropped.txt --verbose
```

`--dropped` names each sentence left out on purpose, with why (the script's help describes the
format). Write a new list for each move and commit it with the move, under `docs/plans/` like the
split's, so a reviewer can run the same comparison. The comparison holds for the commit that moves
the text: later edits of the new files can make a sentence missing again, so it is not a CI check.
`python3 tools/check-moved-text.py --self-test` checks the script itself. Then fix the links into
the old file: `node site/build.mjs --check-repo-markdown` finds every link and heading anchor that
no longer resolves.
